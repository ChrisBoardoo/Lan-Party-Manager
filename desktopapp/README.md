# LPM Desktop

A Slack-style native Windows client for LAN Party Manager: a Tauri shell asks
for your server's URL on first launch, then embeds the real LPM web app
unmodified — same login, same everything. Sits in the system tray with
native Windows toast notifications for crew activity, and auto-updates
itself. Full spec: `desktopplan_windows.md`.

**Status: M0–M3 done and live-verified** against a real deployed instance
— server-URL entry, persistent login,
tray/notifications/settings, Discord SSO, and the installer/auto-updater
pipeline below all work end to end. See `desktopplan_windows.md`'s
milestone list for what shipped in each, and `CLAUDE.md`'s "Known WebView2
gotchas" section (repo root) for the real bugs hit building this — several
cost real debugging time and are worth reading before re-deriving them.

## Prerequisites (one-time)

You need Rust + the Windows C++ build tools. Node/npm are assumed already
installed (this repo's `frontend/` needs them too).

```powershell
# 1. Rust, via rustup (a few hundred MB, a couple of minutes)
winget install Rustlang.Rustup
# restart your terminal after this so `cargo`/`rustc` are on PATH

# 2. Microsoft C++ Build Tools — required for the windows-msvc target Tauri
#    needs. This is the big one: several GB, can take 15-30+ minutes, and the
#    installer UI needs you to tick "Desktop development with C++".
winget install Microsoft.VisualStudio.2022.BuildTools --override "--add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --passive"

# 3. Confirm both landed
cargo --version
rustc --version
```

WebView2 itself doesn't need installing — it ships with Windows 10 (2004+)
and Windows 11.

## Run it (development)

```powershell
cd desktopapp
npm install
npm run dev
```

`npm run dev` → `tauri dev`, which itself starts a Vite dev server for the
shell (`ui/`, port 1420) before launching the Rust app — one command, no
separate terminal needed. First run does a full Rust dependency build
(several minutes, ~400+ crates); subsequent runs are fast since Cargo caches
compiled dependencies. `[lpm]`-prefixed `eprintln!` lines in this terminal
are the primary way to debug anything Tauri-native (window/tray/notification
behavior) — see CLAUDE.md's "Diagnosing frontend issues in the desktop app"
note for when to reach for Playwright against the web app instead.

## Project layout

```
desktopapp/
  ui/                  # the shell — Tauri's frontendDist/devUrl
    index.html           # server-URL screen + settings panel markup
    logo.png
    src/
      main.js             # login flow, message bridge, settings, update check
      styles.css
  icons/app-icon.png   # SOURCE icon for `npm run icon` (not embedded directly)
  vite.config.js       # root: "ui" — bundles ui/ for both dev and build
  package.json
  src-tauri/           # the Rust/Tauri project
    src/main.rs          # window/tray setup, all #[tauri::command]s, polling
    src/lol.rs           # League of Legends end-of-game capture (see below)
    tauri.conf.json       # includes bundle target + updater config (see below)
    capabilities/default.json
    icons/                # generated by `npm run icon`, used by the Windows bundler
```

`ui/` is deliberately its own folder, separate from `src-tauri/` and
`node_modules/` — an early version pointed `frontendDist` at the wrong
folder and walked `src-tauri/target/` (its own build output) as if it were
frontend assets.

## League of Legends stats (`src/lol.rs`)

When the server has **LoL stats** turned on (Settings → features, off by
default), the app watches the League client and sends each finished game's
end-of-game block to `POST /api/lol/matches` — fun customs, ARAM, ranked and
tournament matches alike. The stats show up in Games → League of Legends
tracker: **Global** by default, or one LAN's games. A game played during a LAN
the member RSVP'd "in" to is filed under that LAN (the server decides, in the
app's timezone — the app asks `GET /api/lol/capture-status`); any other game
counts in Global only.

- **What it touches**: only the League client's own local API
  (`https://127.0.0.1:<port>`), read-only, with the port/password from the
  client's `lockfile` — found through Riot's `RiotClientInstalls.json`, so a
  non-default install folder works. No process inspection, no memory reading.
  When the member's settings say no, it doesn't touch the client at all.
- **What it needs**: the member's Riot ID (`Name#TAG`) on their LPM profile —
  the server only accepts a game its sender played in.
- **Member switches**, in the shell's settings panel → "League of Legends",
  both on by default: send my games at all, and *also outside a LAN*. Untick
  the second to keep home games to yourself and only send LAN games.
- **Needs a matching server**: `capture-status` arrived with the server change
  that accepts games outside a LAN — against an older server the app reads
  "paused — server unreachable" and sends nothing.
- **Parsing is server-side** (`backend/lol_capture.py`): a Riot field rename
  is a server redeploy, not a new desktop release.
- **Debugging**: `[lpm] lol:` lines in the `npm run dev` terminal trace every
  step (capture on/off, client found, phase changes, game sent or refused).

## Releasing (installer + auto-update)

Builds an MSI installer and publishes it as a **draft** GitHub Release, which
the updater checks against. MSI over NSIS (`.exe`) specifically because
plenty of browsers/network filters flag or block bare `.exe` downloads
outright — MSI reads as a normal Windows installer format instead.

```powershell
git tag desktop-v1.2.0
git push origin desktop-v1.2.0
```

pushing a `desktop-v*` tag runs `.github/workflows/desktop-release.yml`
(`tauri-apps/tauri-action`), which builds, signs, and uploads the installer
plus `latest.json` (the manifest `@tauri-apps/plugin-updater` polls once per
launch — `ui/src/main.js`'s `checkForUpdates()`). Installed apps poll the copy
published on lanpartymanager.com (`assets/desktop/latest.json`), not the GitHub
release. Review the draft release on GitHub before publishing it — nothing goes
live automatically.

Needs two **GitHub repo secrets** (Settings → Secrets and variables →
Actions), from the signing keypair generated once via
`npx tauri signer generate -w <path outside the repo>`:
`TAURI_SIGNING_PRIVATE_KEY` (the private key file's contents) and
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. **Never commit the private key** — if
it's ever lost, a fresh keypair breaks the update chain for everyone already
installed (they'd need to reinstall manually once, since their copy can no
longer verify updates signed by a new key).

Installers are **unsigned** (no code-signing certificate) — Windows
SmartScreen shows "Windows protected your PC" once per install, dismissed
via "More info → Run anyway." Free, deliberate tradeoff for now; see
`desktopplan_windows.md`'s "Installer, signing, distribution" section for
the SignPath.io plan to remove this later.

`desktopapp/`'s version (`package.json`, `package-lock.json`, `Cargo.toml`,
`Cargo.lock`, `tauri.conf.json`) is a separate number in principle, kept equal
to the server's `version.json` since 1.3.4; `python scripts/check_version_sync.py`
checks all of them together before a release.
